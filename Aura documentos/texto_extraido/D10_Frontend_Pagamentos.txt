1. Visao Geral
Este documento define todos os componentes de frontend relacionados a pagamentos que
podem ser desenvolvidos agora, sem depender da escolha do gateway. A arquitetura e
abstraida: o componente de checkout captura os dados e chama um 
processPayment()
generico, que sera implementado quando o gateway for definido.
Principio Gateway-Agnostic: Todos os componentes neste documento funcionam com
qualquer gateway de pagamento. A integracao especifica fica em uma unica camada de adapter
( src/api/paymentAdapter.ts ), que sera implementada quando o gateway for escolhido.

4.2 RealtimeStatusUpdater
src/components/payments/RealtimeStatusUpdater.tsx
Componente que escuta mudancas de status em tempo real via Supabase Realtime. Quando
o webhook do gateway atualiza o status no banco, a tela atualiza automaticamente sem
refresh:
// Hook generico - funciona com qualquer gateway
export function usePaymentStatus(orderId: string) {
  const queryClient = useQueryClient()
  useEffect(() => {
    const channel = supabase
      .channel(`order_${orderId}`)
      .on('postgres_changes', {
        event: 'UPDATE',
        schema: 'public',
        table: 'orders',
        filter: `id=eq.${orderId}`,
      }, (payload) => {
        queryClient.invalidateQueries({ queryKey: ['order', orderId] })
      })
      .subscribe()
    return () => { supabase.removeChannel(channel) }
  }, [orderId])
}
